## Завдання 1. Дослідження мережі (2 бали)

### Команда

```bash
ip a
```

### Результат команди

```
1: lo: <LOOPBACK,UP,LOWER_UP> mtu 65536 qdisc noqueue state UNKNOWN group default qlen 1000
    link/loopback 00:00:00:00:00:00 brd 00:00:00:00:00:00
    inet 127.0.0.1/8 scope host lo
       valid_lft forever preferred_lft forever
    inet 10.255.255.254/32 brd 10.255.255.254 scope global lo
       valid_lft forever preferred_lft forever
    inet6 ::1/128 scope host proto kernel_lo
       valid_lft forever preferred_lft forever
2: eth0: <BROADCAST,MULTICAST,UP,LOWER_UP> mtu 1280 qdisc mq state UP group default qlen 1000
    link/ether 00:15:5d:7a:ed:c9 brd ff:ff:ff:ff:ff:ff
    altname enx00155d7aedc9
    inet 172.23.61.31/20 brd 172.23.63.255 scope global eth0
       valid_lft forever preferred_lft forever
    inet6 fe80::215:5dff:fe7a:edc9/64 scope link proto kernel_ll
       valid_lft forever preferred_lft forever
```

Для аналізу використано основний мережевий інтерфейс **`eth0`** (активне підключення до мережі).

| Параметр | Значення |
|----------|----------|
| **Інтерфейс** | `eth0` (альтернативна назва: `enx00155d7aedc9`) |
| **Тип підключення** | Ethernet (віртуальний адаптер WSL2 / Hyper-V), проводове подання на рівні L2 |
| **MAC-адреса** | `00:15:5d:7a:ed:c9` |
| **IP-адреса** | `172.23.61.31` — **рівень OSI: 3 (мережевий, Network)** |
| **Маска** | `/20` (`255.255.240.0`) — **рівень OSI: 3 (мережевий, Network)** |
| **Gateway (шлюз за замовчуванням)** | `172.23.48.1` (див. також `ip r`) |
| **Broadcast** | `172.23.63.255` |
| **Hosts (доступні адреси хостів у підмережі)** | Підмережа `172.23.48.0/20`: 2¹² = **4096** адрес загалом; **4094** придатні для хостів (без адреси мережі `172.23.48.0` та broadcast `172.23.63.255`) |

**Коментар.** MAC-адреса належить **канальному рівню (L2)** моделі OSI. IP-адреса та маска підмережі — **мережевому рівню (L3)**. Інтерфейс `lo` — loopback для локальних служб (`127.0.0.1`).

## Завдання 2. Дослідження маршрутизації (2 бали)

### Команда

```bash
ip r
```

### Результат команди

```
default via 172.23.48.1 dev eth0 proto kernel
172.23.48.0/20 dev eth0 proto kernel scope link src 172.23.61.31
```

### Пояснення

- **Маршрут за замовчуванням:** увесь трафік, для якого немає більш специфічного маршруту, йде через шлюз **`172.23.48.1`** інтерфейсом **`eth0`**.
- **Локальна підмережа:** адреси **`172.23.48.0/20`** досяжні напряму через **`eth0`**; джерельна адреса пакетів — **`172.23.61.31`**.
- **Позначка `proto kernel`:** маршрути додані ядром ОС (наприклад, на основі налаштувань інтерфейсу), а не динамічним протоколом маршрутизації (OSPF, BGP тощо).

### Протокол, через який отримано IP

**DHCP** (Dynamic Host Configuration Protocol) — протокол **прикладного рівня** в стеку TCP/IP, який автоматично видає IP-адресу, маску, шлюз і DNS. У домашніх і навчальних мережах IP зазвичай отримують саме через DHCP, а не вручну (статична конфігурація). У середовищі WSL2 адресація також задається автоматично віртуальною мережею хоста (аналогічно до DHCP-підходу).

## Завдання 3. Знаходження публічної IP-адреси (2 бали)

### Команда

```bash
curl ifconfig.io
```

### Результат команди

```
81.162.253.132
```

### Порівняння локальної та публічної адрес

| | Адреса |
|---|--------|
| **Локальна (приватна)** | `172.23.61.31` |
| **Публічна** | `81.162.253.132` |

**Чи вони однакові?** Ні, адреси **різні**.

**Чому?** Адреса `172.23.61.31` належить **приватному діапазону** (RFC 1918: `172.16.0.0/12`) і використовується лише **в локальній мережі** (у домашній LAN або віртуальній мережі WSL). **Домашній роутер** (або NAT на стороні провайдера/хоста) має **одну публічну IP** від ISP і **перекладає (NAT)** вихідний трафік з багатьох приватних адрес пристроїв у цю публічну адресу. Тому з Інтернету видно **`81.162.253.132`**, а не `172.23.61.31`.

**Коментар.** Сервіс `ifconfig.io` показує IP-адресу, з якої ваш запит виходить у глобальну мережу — це і є публічна адреса NAT/роутера. Локальна адреса потрібна для обміну всередині підмережі; для доступу до ресурсів в Інтернеті використовується трансляція адрес на шлюзі. Таке розділення — типова схема домашніх і офісних мереж.
